  144: =head1 DESCRIPTION
  145: 
  146: Signs a message with DKIM when its C<From:> domain is one this host signs for,
  147: and hands it to sendmail with whatever arguments sendmail should have.  The
  148: signed form is C<rsa-sha256> with C<relaxed> canonicalization, which is the
  149: shape receiving sites expect.
  150: 
  151: The signature covers the message in the form DKIM defines, where every line
  152: ends CRLF.  What is handed to sendmail is the local form instead: LF line
  153: endings, and no carriage return anywhere, whatever arrived.  A CR would be data
  154: to the MTA that keeps the message - Postfix and Exim both write the CRLF of
  155: SMTP themselves - so a message that had travelled with CRLF in it would reach
  156: the receiver with the CRs doubled and fail the signature it had just been given.
  157: 
  158: Nothing here dies because a key is missing: signing either produces a signed
  159: message or produces nothing and says why on standard error, so a caller can
  160: always fall back to sending the message as it is.
  161: 
  162: =head1 PLATFORMS

 1079: =head1 A CRONTAB ENTRY
 1080: 
 1081: A job that sends mail from cron is where an unsigned message is least likely to
 1082: be noticed, so that is usually where this module earns its keep: the program
 1083: that ships with it, F<mail-dkim>, is put where the job would have called
 1084: sendmail(1), and the job itself is not changed.
 1085: 
 1086: The weekly summary in this distribution is such a job, and its mail goes out
 1087: through F<mail-dkim>.  A crontab line for it looks like this, with the values of
 1088: the machine it runs on:
 1089: 
 1090: 	0 6 * * 1 DMARC_EXPECTED=192.0.2.10 MAIL_TO=alerts@example.org \
 1091: 		PERL=/usr/bin/perl /usr/local/bin/dmarc-weekly.sh
 1092: 
 1093: The three settings are not optional, because cron starts a job with almost no
 1094: environment.  C<DMARC_EXPECTED> is what makes a sender nobody expected a
 1095: finding, and the run stops with a usage error without it, since guessing would
 1096: excuse every sender.  C<MAIL_TO> is where a week that needs looking at is
 1097: mailed, and is also the address the alert is sent as unless C<MAIL_FROM> says
 1098: otherwise.  C<PERL> has to be an absolute path to a perl that has
 1099: C<XML::PP>, as cron's C<PATH> usually holds only the system one; F<--crontab>
 1100: fills it in with the first perl on the machine that can load the module.
 1101: C<DMARC_DIR> and C<DMARC_ARCHIVE_DIR> are left out of the line because they
 1102: default to C<~/Downloads> and C<~/dmarc-archive>.
 1103: 
 1104: F<dmarc-weekly.sh --crontab> prints that line with the path and the perl filled
 1105: in for the machine it runs on, which is more use than an example carrying
 1106: somebody else's values; for that reason no example crontab file is shipped or
 1107: installed.  A job of your own takes the same shape with F<mail-dkim> in place of
 1108: the wrapper: C<DKIM_DOMAINS> and C<DKIM_KEYDIR> say what to sign for, and the
 1109: arguments given to it are passed to sendmail(1) as they are.
 1110: 
 1111: =head1 COMMON PITFALLS
 1112: 
 1113: =over 4
 1114: 
 1115: =item * B<sign> returns C<undef> to mean "nothing was signed"
 1116: 
 1117: It does not die and it does not return an empty string.  Always test with
 1118: C<defined>.  The reason is a warning on standard error, except when the
 1119: message simply is not from one of your domains: that is normal and says
 1120: nothing.  Keep the original message and send it if B<sign> gave you C<undef>.
 1121: 
 1122: =item * An C<undef> option means "not given"
 1123: 
 1124: C<< new(keydir => undef) >> is the same as leaving C<keydir> out: the
 1125: environment variable, then the built-in default, is used.  An empty string is
 1126: a value: C<< domains => '' >> means "sign for no domain", and nothing is
 1127: signed.
 1128: 
 1129: =item * Replacing a message replaces all of it
 1130: 
 1131: The C<messages> option is merged one level deep.  A key you give replaces the
 1132: whole entry for that key.  If the English entry has the forms C<one> and
 1133: C<other> and you give only C<other>, the C<one> form is gone: it does not fall
 1134: back to English.  Give every form you need.
 1135: 
 1136: =item * Every placeholder needs a value
 1137: 
 1138: A message such as C<%{error}s> is filled from the arguments given to B<i18n>.
 1139: A placeholder with no value is an error (a croak), not an empty space.  The
 1140: placeholder style is C<%{name}s>, not C<%s>.
 1141: 
 1142: =item * Exit status C<0> means "accepted", not "delivered"
 1143: 
 1144: B<send> only knows that sendmail took the message.  A later failure is the
 1145: mail system's to report.  Call B<log_send> only after a C<0>.
 1146: 
 1147: =item * The signed message is not the same text as the one you gave
 1148: 
 1149: Carriage returns are removed, so the result has LF line endings.  This is on
 1150: purpose, and B<send> does the same.  Do not compare the two with C<eq>.
 1151: 
 1152: =item * Only the first C<From:> header counts
 1153: 
 1154: A message with two C<From:> headers is signed for the domain of the first one.
 1155: 
 1156: =item * Several keys, no name
 1157: 
 1158: If the key directory holds more than one F<*.private> file and you give no
 1159: B<selector>, nothing is signed, and there is a warning.  Name the selector.
 1160: 
 1161: =item * C<~> is not expanded
 1162: 
 1163: C<< keydir => '~/dkim' >> means a directory that is really called C<~>.  Use
 1164: the full path, or C<$ENV{HOME}>.
 1165: 
 1166: =item * Private and protected methods
 1167: 
 1168: Names that start with an underscore cannot be called from outside the package.
 1169: Under a test harness (C<HARNESS_ACTIVE> is set) the check is switched off, so
 1170: that tests can reach them.
 1171: 
 1172: =back

 1174: =head1 ENCODING
 1175: 
 1176: The module works on B<bytes>, not on decoded characters, because DKIM signs
 1177: bytes.
 1178: 
 1179: =over 4
 1180: 
 1181: =item * The message
 1182: 
 1183: Give B<sign>, B<send>, B<log_send> and B<from_domain> a message that is
 1184: already encoded, normally as UTF-8 bytes.  Non-ASCII text and emojis in the
 1185: subject or the body are safe in that form.  Mail systems usually expect a
 1186: non-ASCII header to be MIME encoded (for example C<=?UTF-8?B?...?=>), and that
 1187: is your job, not this module's.
 1188: 
 1189: If the message is a Perl string holding characters above code point 255 (an
 1190: emoji that has been decoded, for example), B<sign> cannot sign it: there is a
 1191: warning and it returns C<undef>.  B<send> would write it as UTF-8 and Perl
 1192: would warn "Wide character".  Call C<Encode::encode('UTF-8', $text)> first.
 1193: 
 1194: =item * Domains and selectors
 1195: 
 1196: ASCII only.  The domain taken from C<From:> must be letters, digits, dots and
 1197: hyphens, or it is treated as no domain.  An internationalised domain name must
 1198: be written in its C<xn--> form.  Selectors are used as file names and in DNS,
 1199: so use letters, digits and hyphens.
 1200: 
 1201: =item * File names
 1202: 
 1203: B<keydir>, B<keyfile> and B<sendmail> are passed to the operating system as
 1204: they are.  Non-ASCII names work if the bytes are what the file system holds.
 1205: 
 1206: =item * The log line
 1207: 
 1208: B<log_send> writes the sender, recipients and subject as they are.  UTF-8 bytes
 1209: and emojis are kept.  Control characters, such as a line break, are replaced by
 1210: a space.
 1211: 
 1212: =item * Message texts
 1213: 
 1214: The text given in C<messages> may contain any characters, emojis included.
 1215: Warnings go to standard error: put a UTF-8 layer on it
 1216: (C<binmode(STDERR, ':encoding(UTF-8)')>) when the text is not ASCII, or Perl
 1217: will warn "Wide character".  The text of an operating system error comes from
 1218: the locale of the process.
 1219: 
 1220: =back

 1222: =head1 LIMITATIONS
 1223: 
 1224: These are the weaknesses of the design, set down so that they are chosen rather
 1225: than found.
 1226: 
 1227: =over 4
 1228: 
 1229: =item * One key for every domain
 1230: 
 1231: A single selector and key serve every domain in C<domains>.  A host that signs
 1232: for several customers with a key each cannot say so; it needs one object per
 1233: key.
 1234: 
 1235: =item * Only the From: domain is looked at
 1236: 
 1237: A message is signed when its first C<From:> domain is ours.  A message with two
 1238: C<From:> headers is signed with the first one's domain, and the signature does
 1239: not oversign the header, so a second C<From:> can be added later without
 1240: breaking it.  Refusing such a message would be the safer rule.
 1241: 
 1242: =item * The key is not checked
 1243: 
 1244: That the key file is readable is checked; its mode is not, and nor is whether
 1245: the public half is published in DNS.  A key that is readable by others is not
 1246: reported.
 1247: 
 1248: =item * The whole message is in memory
 1249: 
 1250: The message is a string, held two or three times over while it is signed.  A
 1251: very large message costs that much memory; a stream would not.
 1252: 
 1253: =item * Sending cannot be interrupted
 1254: 
 1255: B<send> waits for sendmail as long as sendmail takes.  There is no timeout.
 1256: 
 1257: =item * A bare carriage return is removed
 1258: 
 1259: The local form has no CR at all, as specified, so a lone CR inside a line is
 1260: deleted instead of becoming a line break, and the two halves of the line join.
 1261: 
 1262: =item * Addresses are RFC 822
 1263: 
 1264: L<Mail::Address> is a lenient RFC 822 parser.  Internationalised addresses and
 1265: domain names are not understood, and a From: domain that is not plain ASCII is
 1266: treated as having none.
 1267: 
 1268: =item * The messages are English, with English plurals
 1269: 
 1270: The catalogue is English.  C<count> knows C<zero>, C<one> and C<other>, which is
 1271: not enough for languages with more plural forms; a translation that needs them
 1272: would be better served by L<Locale::Maketext>, which this module does not use
 1273: to avoid a language class for six sentences.  The text of an operating system
 1274: error follows the locale of the process that raised it, which this module does
 1275: not control.
 1276: 
 1277: =item * log_send reads sendmail's options approximately
 1278: 
 1279: B<log_send> knows which of sendmail's options take a value, but not every
 1280: MTA's.  An option it has not heard of that takes a value would have that value
 1281: logged as a recipient.
 1282: 
 1283: =item * rsa-sha256 only
 1284: 
 1285: There is one signature, C<rsa-sha256> with C<relaxed> canonicalization.  Ed25519
 1286: and a second signature are not offered.
 1287: 
 1288: =item * Windows
 1289: 
 1290: L</PLATFORMS> applies.
 1291: 
 1292: =item * Private means private
 1293: 
 1294: The helpers whose names begin with an underscore are enforced private
 1295: (L<Sub::Private>) and the message writer is protected (L<Sub::Protected>), at
 1296: the cost of a check on every call.  A subclass cannot replace a private helper.
 1297: 
 1298: =back

 1431: =head1 STATE DIAGRAM
 1432: 
 1433: The object itself has one state.  B<new> builds it, and nothing afterwards
 1434: changes it: B<sign>, B<send>, B<log_send>, B<selector> and B<i18n> only read it.

 1436: is the diagram of that journey.
