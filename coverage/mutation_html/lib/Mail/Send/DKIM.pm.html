  147: =head1 DESCRIPTION
  148: 
  149: Signs a message with DKIM when its C<From:> domain is one this host signs for,
  150: and hands it to sendmail with whatever arguments sendmail should have.  The
  151: signed form is C<rsa-sha256> with C<relaxed> canonicalization, which is the
  152: shape receiving sites expect.
  153: 
  154: The signature covers the message in the form DKIM defines, where every line
  155: ends CRLF.  What is handed to sendmail is the local form instead: LF line
  156: endings, and no carriage return anywhere, whatever arrived.  A CR would be data
  157: to the MTA that keeps the message - Postfix and Exim both write the CRLF of
  158: SMTP themselves - so a message that had travelled with CRLF in it would reach
  159: the receiver with the CRs doubled and fail the signature it had just been given.
  160: 
  161: Nothing here dies because a key is missing: signing either produces a signed
  162: message or produces nothing and says why on standard error, so a caller can
  163: always fall back to sending the message as it is.
  164: 
  165: =head1 PLATFORMS

 1136: =head1 A CRONTAB ENTRY
 1137: 
 1138: A job that sends mail from cron is where an unsigned message is least likely to
 1139: be noticed, so that is usually where this module earns its keep: the program
 1140: that ships with it, F<mail-dkim>, is put where the job would have called
 1141: sendmail(1), and the job itself is not changed.
 1142: 
 1143: The weekly summary in this distribution is such a job, and its mail goes out
 1144: through F<mail-dkim>.  A crontab line for it looks like this, with the values of
 1145: the machine it runs on:
 1146: 
 1147: 	0 6 * * 1 DMARC_EXPECTED=192.0.2.10 MAIL_TO=alerts@example.org \
 1148: 		PERL=/usr/bin/perl /usr/local/bin/dmarc-weekly.sh
 1149: 
 1150: The three settings are not optional, because cron starts a job with almost no
 1151: environment.  C<DMARC_EXPECTED> is what makes a sender nobody expected a
 1152: finding, and the run stops with a usage error without it, since guessing would
 1153: excuse every sender.  C<MAIL_TO> is where a week that needs looking at is
 1154: mailed, and is also the address the alert is sent as unless C<MAIL_FROM> says
 1155: otherwise.  C<PERL> has to be an absolute path to a perl that has
 1156: C<XML::PP>, as cron's C<PATH> usually holds only the system one; F<--crontab>
 1157: fills it in with the first perl on the machine that can load the module.
 1158: C<DMARC_DIR> and C<DMARC_ARCHIVE_DIR> are left out of the line because they
 1159: default to C<~/Downloads> and C<~/dmarc-archive>.
 1160: 
 1161: F<dmarc-weekly.sh --crontab> prints that line with the path and the perl filled
 1162: in for the machine it runs on, which is more use than an example carrying
 1163: somebody else's values; for that reason no example crontab file is shipped or
 1164: installed.  A job of your own takes the same shape with F<mail-dkim> in place of
 1165: the wrapper: C<DKIM_DOMAINS> and C<DKIM_KEYDIR> say what to sign for, and the
 1166: arguments given to it are passed to sendmail(1) as they are.

 1168: =head1 COMMON PITFALLS
 1169: 
 1170: =over 4
 1171: 
 1172: =item * B<sign> returns C<undef> to mean "nothing was signed"
 1173: 
 1174: It does not die and it does not return an empty string.  Always test with
 1175: C<defined>.  The reason is a warning on standard error, except when the
 1176: message simply is not from one of your domains: that is normal and says
 1177: nothing.  Keep the original message and send it if B<sign> gave you C<undef>.
 1178: 
 1179: =item * An C<undef> option means "not given"
 1180: 
 1181: C<< new(keydir => undef) >> is the same as leaving C<keydir> out: the
 1182: environment variable, then the built-in default, is used.  An empty string is
 1183: a value: C<< domains => '' >> means "sign for no domain", and nothing is
 1184: signed.
 1185: 
 1186: =item * Replacing a message replaces all of it
 1187: 
 1188: The C<messages> option is merged one level deep.  A key you give replaces the
 1189: whole entry for that key.  If the English entry has the forms C<one> and
 1190: C<other> and you give only C<other>, the C<one> form is gone: it does not fall
 1191: back to English.  Give every form you need.
 1192: 
 1193: =item * Every placeholder needs a value
 1194: 
 1195: A message such as C<%{error}s> is filled from the arguments given to B<i18n>.
 1196: A placeholder with no value is an error (a croak), not an empty space.  The
 1197: placeholder style is C<%{name}s>, not C<%s>.
 1198: 
 1199: =item * Exit status C<0> means "accepted", not "delivered"
 1200: 
 1201: B<send> only knows that sendmail took the message.  A later failure is the
 1202: mail system's to report.  Call B<log_send> only after a C<0>.
 1203: 
 1204: =item * The signed message is not the same text as the one you gave
 1205: 
 1206: Carriage returns are removed, so the result has LF line endings.  This is on
 1207: purpose, and B<send> does the same.  Do not compare the two with C<eq>.
 1208: 
 1209: =item * Only the first C<From:> header counts
 1210: 
 1211: A message with two C<From:> headers is signed for the domain of the first one.
 1212: 
 1213: =item * Several keys, no name
 1214: 
 1215: If the key directory holds more than one F<*.private> file and you give no
 1216: B<selector>, nothing is signed, and there is a warning.  Name the selector.
 1217: 
 1218: =item * C<~> is not expanded
 1219: 
 1220: C<< keydir => '~/dkim' >> means a directory that is really called C<~>.  Use
 1221: the full path, or C<$ENV{HOME}>.
 1222: 
 1223: =item * Private and protected methods
 1224: 
 1225: Names that start with an underscore cannot be called from outside the package.
 1226: Under a test harness (C<HARNESS_ACTIVE> is set) the check is switched off, so
 1227: that tests can reach them.

 1231: =head1 ENCODING
 1232: 
 1233: The module works on B<bytes>, not on decoded characters, because DKIM signs
 1234: bytes.
 1235: 
 1236: =over 4
 1237: 
 1238: =item * The message
 1239: 
 1240: Give B<sign>, B<send>, B<log_send> and B<from_domain> a message that is
 1241: already encoded, normally as UTF-8 bytes.  Non-ASCII text and emojis in the
 1242: subject or the body are safe in that form.  Mail systems usually expect a
 1243: non-ASCII header to be MIME encoded (for example C<=?UTF-8?B?...?=>), and that
 1244: is your job, not this module's.
 1245: 
 1246: If the message is a Perl string holding characters above code point 255 (an
 1247: emoji that has been decoded, for example), B<sign> cannot sign it: there is a
 1248: warning and it returns C<undef>.  B<send> would write it as UTF-8 and Perl
 1249: would warn "Wide character".  Call C<Encode::encode('UTF-8', $text)> first.
 1250: 
 1251: =item * Domains and selectors
 1252: 
 1253: ASCII only.  The domain taken from C<From:> must be letters, digits, dots and
 1254: hyphens, or it is treated as no domain.  An internationalised domain name must
 1255: be written in its C<xn--> form.  Selectors are used as file names and in DNS,
 1256: so use letters, digits and hyphens.
 1257: 
 1258: =item * File names
 1259: 
 1260: B<keydir>, B<keyfile> and B<sendmail> are passed to the operating system as
 1261: they are.  Non-ASCII names work if the bytes are what the file system holds.
 1262: 
 1263: =item * The log line
 1264: 
 1265: B<log_send> writes the sender, recipients and subject as they are.  UTF-8 bytes
 1266: and emojis are kept.  Control characters, such as a line break, are replaced by
 1267: a space.
 1268: 
 1269: =item * Message texts
 1270: 
 1271: The text given in C<messages> may contain any characters, emojis included.
 1272: Warnings go to standard error: put a UTF-8 layer on it
 1273: (C<binmode(STDERR, ':encoding(UTF-8)')>) when the text is not ASCII, or Perl
 1274: will warn "Wide character".  The text of an operating system error comes from
 1275: the locale of the process.
 1276: 
 1277: =back

 1279: =head1 LIMITATIONS
 1280: 
 1281: These are the weaknesses of the design, set down so that they are chosen rather
 1282: than found.
 1283: 
 1284: =over 4
 1285: 
 1286: =item * One key for every domain
 1287: 
 1288: A single selector and key serve every domain in C<domains>.  A host that signs
 1289: for several customers with a key each cannot say so; it needs one object per
 1290: key.
 1291: 
 1292: =item * Only the From: domain is looked at
 1293: 
 1294: A message is signed when its first C<From:> domain is ours.  A message with two
 1295: C<From:> headers is signed with the first one's domain, and the signature does
 1296: not oversign the header, so a second C<From:> can be added later without
 1297: breaking it.  Refusing such a message would be the safer rule.
 1298: 
 1299: =item * The key is not checked
 1300: 
 1301: That the key file is readable is checked; its mode is not, and nor is whether
 1302: the public half is published in DNS.  A key that is readable by others is not
 1303: reported.
 1304: 
 1305: =item * The whole message is in memory
 1306: 
 1307: The message is a string, held two or three times over while it is signed.  A
 1308: very large message costs that much memory; a stream would not.
 1309: 
 1310: =item * Sending cannot be interrupted
 1311: 
 1312: B<send> waits for sendmail as long as sendmail takes.  There is no timeout.
 1313: 
 1314: =item * A bare carriage return is removed
 1315: 
 1316: The local form has no CR at all, as specified, so a lone CR inside a line is
 1317: deleted instead of becoming a line break, and the two halves of the line join.
 1318: 
 1319: =item * Addresses are RFC 822
 1320: 
 1321: L<Mail::Address> is a lenient RFC 822 parser.  Internationalised addresses and
 1322: domain names are not understood, and a From: domain that is not plain ASCII is
 1323: treated as having none.
 1324: 
 1325: =item * The messages are English, with English plurals
 1326: 
 1327: The catalogue is English.  C<count> knows C<zero>, C<one> and C<other>, which is
 1328: not enough for languages with more plural forms; a translation that needs them
 1329: would be better served by L<Locale::Maketext>, which this module does not use
 1330: to avoid a language class for six sentences.  The text of an operating system
 1331: error follows the locale of the process that raised it, which this module does
 1332: not control.
 1333: 
 1334: =item * log_send reads sendmail's options approximately
 1335: 
 1336: B<log_send> knows which of sendmail's options take a value, but not every
 1337: MTA's.  An option it has not heard of that takes a value would have that value
 1338: logged as a recipient.
 1339: 
 1340: =item * rsa-sha256 only
 1341: 
 1342: There is one signature, C<rsa-sha256> with C<relaxed> canonicalization.  Ed25519
 1343: and a second signature are not offered.
 1344: 
 1345: =item * Windows
 1346: 
 1347: L</PLATFORMS> applies.
 1348: 
 1349: =item * Private means private
 1350: 
 1351: The helpers whose names begin with an underscore are enforced private
 1352: (L<Sub::Private>) and the message writer is protected (L<Sub::Protected>), at
 1353: the cost of a check on every call.  A subclass cannot replace a private helper.
 1354: 
 1355: =back
